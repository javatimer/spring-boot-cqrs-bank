### Сигналы: базовые блоки состояния приложения

Традиционные веб-приложения используют JavaScript для изменения содержимого HTML-страницы путем прямого манипулирования DOM-деревом. Приложение на Angular делает то же самое, но сам фреймворк спроектирован так, что вам практически никогда не приходится обращаться к DOM или изменять его вручную в своем коде.

Вместо этого вы пишете HTML-шаблоны, которые отображают данные, содержащиеся в свойствах компонента. Магия Angular заключается в том, что для обновления DOM достаточно просто изменить данные внутри компонента. Angular автоматически отслеживает эти изменения и сам применяет обновления к DOM. Этот механизм называется **Отслеживанием изменений** (*Change Detection*). Мы подробно изучим его далее в книге.

Angular всегда позволял разработчикам использовать обычные объекты и массивы JavaScript для хранения данных, выводимых в шаблонах. Фреймворк умеет отслеживать модификации или замену таких стандартных объектов. Однако этот механизм работает довольно "влоб", несёт ощутимые затраты с точки зрения производительности и обладает рядом недостатков.

Начиная с Angular 16, началась настоящая революция. Сохраняя поддержку прежнего подходу, Angular теперь продвигает новый способ управления состоянием. Этот новый подход устраняет недостатки механизма "влоб" и делает работу приложения значительно эффективнее. Однако он требует от разработчиков использования специального типа объектов для хранения данных — **сигналов** (*signals*).

### 9.1. Что такое сигнал?

Сигнал — это своего рода «контейнер» (или коробка), который всегда содержит некоторое значение. Вы можете получить значение внутри контейнера, «прочитав» сигнал. Если сигнал доступен для записи, вы можете поместить туда другое значение, установив или обновив его.

Значением внутри контейнера может быть что угодно: число, строка, объект, массив или даже `null` / `undefined`.

Эти контейнеры наделены суперсилой. Когда шаблон компонента читает сигнал для отображения его значения, Angular запоминает, что этот шаблон зависит от данного сигнала. И теперь каждый раз, когда вы обновляете сигнал новым значением, Angular точно знает, что ему необходимо обновить участок DOM, сгенерированный этим шаблоном.

В этом и заключается принцип нового механизма отслеживания изменений в Angular. Если все компоненты используют сигналы для хранения данных, отображаемых в их шаблонах, то старый механизма "влоб" больше не нужен.

Революция, начавшаяся в Angular 16, всё ещё продолжается. Однако все возможности, связанные с сигналами и представленные с тех пор, уже достаточно стабильны, и мы можем смело использовать их в своих приложениях.

Эта книга описывает работу с Angular в новом, современном стиле, основанном на сигналах. Тем не менее, мы будем упоминать и то, как задачи решались раньше, так как существует высокая вероятность, что в существующих проектах вы встретите код, написанный устаревшим способом. Оба подхода могут сосуществовать в одном приложении, но мы настоятельно рекомендуем переходить на новые лучшие практики.

### 9.2. Создание, чтение и запись сигналов

Давайте посмотрим, как можно создать записываемый сигнал, прочитать его значение и обновить его. О других видах сигналов и их дополнительных возможностях мы поговорим в следующих главах, когда они понадобятся.

Чтобы создать записываемый сигнал, вызовите функцию `signal()` (из пакета `@angular/core`), передав ей начальное значение. Все приведенные ниже примеры создают экземпляры `WritableSignal` — дженерик-типа, указывающего на тип содержимого внутри сигнала:

```typescript
// Этот сигнал содержит число, начальное значение — 42
const count = signal(42);

// Этот сигнал содержит PonyModel, начальное значение — Rainbow Dash
const rainbowDash = signal<PonyModel>({
  name: 'Rainbow Dash',
  color: 'blue'
});

// Этот сигнал содержит PonyModel, начальное значение — Pinkie Pie
const pinkiePie: WritableSignal<PonyModel> = signal({
  name: 'Pinkie Pie',
  color: 'red'
});

// Этот сигнал содержит PonyModel или undefined, начальное значение — undefined
const unknownPony = signal<PonyModel | undefined>(undefined);

```

Сигнал одновременно является и объектом, и функцией. Чтобы **прочитать** значение, содержащееся в сигнале, достаточно вызвать его как функцию:

```typescript
// Читаем значение сигнала rainbowDash
const value: PonyModel = rainbowDash();

// Выводим его в консоль в формате JSON
console.log(JSON.stringify(value));

```

Чтобы **изменить** значение сигнала (и тем самым уведомить Angular о том, что у сигнала новое значение), используйте метод `.set()`:

```typescript
rainbowDash.set({
  name: 'Rainbow Dash',
  color: 'yellow'
});

```

Теперь представим, что вы хотите изменить только цвет у `Rainbow Dash`. У вас может возникнуть соблазн прочитать значение сигнала и напрямую мутировать его свойство. Или мутировать его, а затем передать обратно через `.set()`. **Никогда так не делайте:**

```typescript
// ❌ НЕ ДЕЛАЙТЕ ТАК!
rainbowDash().color = 'yellow';

// ❌ НЕ ДЕЛАЙТЕ ТАК!
const pony = rainbowDash();
pony.color = 'yellow';
rainbowDash.set(pony);

```

Если вы мутируете объект внутри сигнала или передаете в метод `.set()` тот же самый объект, который там уже лежал, Angular посчитает, что значение не изменилось, и это приведет к багам.

Вместо этого относитесь к значению как к **неизменяемому** (*immutable*) и заменяйте старый объект новым. Для создания нового значения на основе текущего удобно использовать метод `.update()` в комбинации с оператором спреда (деструктуризацией):

```typescript
// ✅ ДЕЛАЙТЕ ТАК!
rainbowDash.update(pony => ({ ...pony, color: 'yellow' }));

```

По сути, это просто более удобная запись следующего действия:

```typescript
rainbowDash.set({ ...rainbowDash(), color: 'yellow' });

```

Теперь давайте разберем, как отображать состояние наших компонентов внутри шаблона!

> **Интересный факт:** Angular — далеко не первый фреймворк, использующий сигналы. Например, Knockout.js применял похожую концепцию очень давно. В последнее время Solid.js, Vue и Svelte также выбрали сигналы в качестве основы для управления состоянием. Сигналы стали настолько популярны, что команды этих фреймворков совместно работают над стандартизацией сигналов на уровне самого языка JavaScript!

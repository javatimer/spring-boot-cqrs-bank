### Стилизация компонентов и инкапсуляция

Давайте ненадолго остановимся и поговорим о стилях и CSS.

Понимаю вашу реакцию: зачем вообще говорить о «чертовом CSS»? Но дело в том, что Angular делает за нас очень много работы за кулисами.

Как веб-разработчик, вы часто добавляете CSS-классы к элементам. Суть CSS заключается в каскадировании (*cascade*). Иногда это именно то, что нужно (например, изменить шрифт во всем приложении), но иногда — нет.

Представьте, что вам нужно стилизовать выбранный элемент в списке: обычно вы используете узкий CSS-селектор вроде `li.selected` или ещё более специфичную запись по методологии BEM, чтобы стили применились только к конкретному месту в приложении.

Именно здесь Angular приходит на помощь. Стили, которые вы определяете внутри компонента (через свойство `styles` или в отдельном файле через `styleUrl` / `styleUrls`), **ограничиваются контекстом только этого компонента**. Это называется **инкапсуляцией стилей** (*style encapsulation*).

Как Angular этого добивается?

Всё начинается с написанных вами стилей. Далее всё зависит от выбранной стратегии инкапсуляции в декораторе компонента. Свойство `encapsulation` может принимать три значения:

* `ViewEncapsulation.Emulated` — режим по умолчанию;
* `ViewEncapsulation.ShadowDom` — использует нативный Shadow DOM v1;
* `ViewEncapsulation.None` — полностью отключает инкапсуляцию.

Каждая стратегия ведет себя по-своему. Давайте разберем их на примере уже знакомого компонента `Pony`:

```typescript
import { Component, signal, ViewEncapsulation } from '@angular/core';

@Component({
  selector: 'ns-pony',
  template: `<div class="red">{{ name() }}</div>`,
  styles: [
    `
      .red {
        color: red;
      }
    `
  ],
  // То же самое, что и режим по умолчанию
  encapsulation: ViewEncapsulation.Emulated
})
export class Pony {
  protected readonly name = signal('Rainbow Dash');
}

```

Мы хотим отобразить имя пони красным цветом с помощью класса `.red`.

---

#### 13.1. Стратегия Shadow DOM (`ViewEncapsulation.ShadowDom`)

Выбирая режим `ShadowDom`, вы указываете Angular использовать механизм **Shadow DOM** вашего браузера (часть спецификации Web Components). Shadow DOM позволяет изолировать структуру и стили компонента от основного дерева DOM.

Если инспектировать сгенерированный DOM в браузере с этой стратегией, мы увидим:

```html
<ns-pony>
  #shadow-root (open)
    <style>.red {color: red}</style>
    <div class="red">Rainbow Dash</div>
</ns-pony>

```

В инспекторе отображается узел `#shadow-root (open)`, а блок `<style>` помещается прямо в начало содержимого компонента.

При использовании `ShadowDom` вы можете быть уверены, что стили вашего компонента не будут «протекать» (*bleed*) в дочерние компоненты, если они также используют Shadow DOM.

> **Примечание:** Shadow DOM — относительно новая спецификация, и она поддерживается не во всех старых средах. Проверяйте совместимость на сайтах вроде *caniuse.com*. Кроме того, для корректной работы этой стратегии селектор компонента обязан содержать дефис (например, `ns-pony`).

---

#### 13.2. Стратегия Emulated (`ViewEncapsulation.Emulated`)

Это стратегия **по умолчанию**. Она эмулирует поведение Shadow DOM, но без применения нативного Shadow DOM браузера, благодаря чему безопасно работает абсолютно во всех браузерах.

Чтобы достичь изоляции, Angular берет CSS-стили компонента и встраивает их в тег `<head>` страницы (а не внутрь самого компонента). Но перед этим Angular переписывает CSS-селекторы, добавляя к ним уникальный атрибут-идентификатор. Этот же атрибут автоматически добавляется ко всем HTML-элементам в шаблоне компонента.

Пример итогового HTML и CSS:

```html
<html>
  <head>
    <style>.red[_ngcontent-dvb-3] {color: red}</style>
  </head>
  <body>
    ...
    <ns-pony _ngcontent-dvb-2="" _nghost-dvb-3="">
      <div _ngcontent-dvb-3="" class="red">Rainbow Dash</div>
    </ns-pony>
  </body>
</html>

```

Селектор `.red` превратился в `.red[_ngcontent-dvb-3]`. Соответственно, стили применятся только к элементам, имеющим одновременно класс `red` и атрибут `_ngcontent-dvb-3`.

Обратите внимание на атрибуты элемента `<ns-pony>`:

* `_ngcontent-dvb-2` — уникальный идентификатор родительского компонента;
* `_nghost-dvb-3` — уникальный идентификатор самого хост-элемента (*host element*).

---

#### 13.3. Стратегия None (`ViewEncapsulation.None`)

В этом режиме инкапсуляция полностью отключается. Стили добавляются в `<head>` страницы (как в режиме `Emulated`), но не переписываются. Они становятся глобальными и обычным образом каскадируются на все дочерние элементы в приложении.

---

#### 13.4. Стилизация хост-элемента (`:host`)

Для стилизации самого тега-контейнера компонента (хост-элемента, например `<ns-pony>`) используется специальный псевдокласс `:host`, пришедший из спецификации Web Components:

```css
:host {
  display: block;
}

```

* При `ViewEncapsulation.ShadowDom` этот селектор сохраняется как `:host`.
* При `ViewEncapsulation.Emulated` Angular автоматически перепишет его в атрибут вида `[_nghost-xxx]`.

---

#### Итоги

Благодаря стратегии `Emulated`, работающей по умолчанию, вам не нужно предпринимать никаких сложных действий для изоляции стилей компонентов. Вы можете переключиться на `ShadowDom`, если ориентируетесь только на современные браузеры, или на `None`, если вам нужны глобальные CSS-правила. Стратегию можно менять как индивидуально для каждого компонента, так и глобально для всего приложения.

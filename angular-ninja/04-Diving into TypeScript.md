### Погружение в TypeScript

TypeScript существует с 2012 года. Это надмножество (superset) языка JavaScript, расширяющее ES5. Самое главное его нововведение — система типов, которая и дала языку название. Начиная с версии 1.5 (выпущенной в 2015 году), библиотека стремится быть надмножеством стандарта ES2015+, включая все современные фичи, которые мы рассмотрели в предыдущей главе, а также некоторые новые возможности, такие как декораторы.

Написание кода на TypeScript очень похоже на JavaScript. По соглашению файлы TypeScript имеют расширение `.ts`. Перед исполнением их необходимо скомпилировать в стандартный JavaScript (обычно это происходит на этапе сборки) с помощью компилятора TypeScript. Сгенерированный код получается очень читаемым.

```bash
npm install -g typescript
tsc test.ts

```

Но давайте начнем с самого начала.

---

### 4.1. Типы в TypeScript

Общий синтаксис добавления информации о типах в TypeScript достаточно прост:

```typescript
let variable: type;

```

Базовые типы легко запомнить:

```typescript
const ponyNumber: number = 0;
const ponyName: string = 'Rainbow Dash';

```

В подобных случаях явное указание типов необязательно, так как компилятор TS может вывести их самостоятельно (это называется «выводом типов» / *type inference*) на основе присвоенных значений.

Типом также может выступать класс из вашего приложения, как в случае с классом `Pony`:

```typescript
const pony: Pony = new Pony();

```

TypeScript поддерживает то, что в некоторых языках называется «обобщениями» (generics), например, для массивов:

```typescript
const ponies: Array<Pony> = [new Pony()];

```

Этот массив может содержать только объекты `Pony`, на что и указывает дженерик-синтаксис с использованием `<>`.

Зачем это нужно? Добавление информации о типах помогает компилятору отлавливать потенциальные ошибки ещё на этапе разработки:

```typescript
ponies.push('hello'); 
// Ошибка TS2345: Аргумент типа 'string' нельзя присвоить параметру типа 'Pony'.

```

Но что делать, если переменная должна принимать значения разных типов? Означает ли это, что всё пропало? Нет, потому что в TS есть специальный тип — `any`:

```typescript
let changing: any = 2;
changing = true; // всё в порядке

```

Он полезен, когда тип значения заранее неизвестен (например, данные приходят из динамического источника или сторонней библиотеки).

Если же переменная может быть только определенным набором типов (например, `number` или `boolean`), можно использовать **объединение типов** (*union type*):

```typescript
let changing: number | boolean = 2;
changing = true; // всё в порядке

```

### 4.2. Перечисления (Enums)

TypeScript также предлагает перечисления (`enum`). Например, гонка в нашем приложении может находиться в состоянии `Ready`, `Started` или `Done`:

```typescript
enum RaceStatus {
  Ready,
  Started,
  Done
}

const race = new Race();
race.status = RaceStatus.Ready;

```

Под капотом `enum` представляет собой числовые значения, начиная с `0`. Однако вы можете явно задать нужные значения:

```typescript
enum Medal {
  Gold = 1,
  Silver,
  Bronze
}

```

Начиная с TypeScript 2.4, в перечислениях можно использовать и строковые значения:

```typescript
enum Position {
  First = 'First',
  Second = 'Second',
  Other = 'Other'
}

```

Честно говоря, в своих проектах мы редких прибегаем к `enum` — вместо них мы чаще используем объединения типов (*union types*). Они проще и закрывают ровно те же сценарии:

```typescript
let color: 'blue' | 'red' | 'green';
// мы можем присвоить переменной `color` только одно из этих значений
color = 'blue';

```

TypeScript даже позволяет создавать собственные псевдонимы типов:

```typescript
type Color = 'blue' | 'red' | 'green';
const ponyColor: Color = 'blue';

```

### 4.3. Возвращаемые типы

Вы можете указывать тип значения, возвращаемого функцией:

```typescript
function startRace(race: Race): Race {
  race.status = RaceStatus.Started;
  return race;
}

```

Если функция ничего не возвращает, это можно явно обозначить с помощью `void`:

```typescript
function startRace(race: Race): void {
  race.status = RaceStatus.Started;
}

```

### 4.4. Интерфейсы

Это отличный первый шаг. Но, как я уже упоминал, JavaScript прекрасен своей динамической природой. Функция будет работать, если она получает объект с нужным свойством:

```javascript
function addPointsToScore(player, points) {
  player.score += points;
}

```

Эта функция применима к любому объекту, у которого есть свойство `score`. Как выразить это в TypeScript? Очень просто: определив **интерфейс**, который задает «форму» (структуру) объекта.

```typescript
function addPointsToScore(
  player: {
    score: number;
  },
  points: number
): void {
  player.score += points;
}

```

Это означает, что передаваемый параметр обязан иметь свойство `score` типа `number`.

Интерфейсам, разумеется, можно давать имена:

```typescript
interface HasScore {
  score: number;
}

function addPointsToScore(player: HasScore, points: number): void {
  player.score += points;
}

```

Вы увидите, что мы постоянно используем интерфейсы на страницах этой книги для описания сущностей. Мы также применяем интерфейсы для моделей в наших коммерческих проектах, добавляя суффикс `Model` для наглядности.

Создавать новые сущности с ними очень удобно:

```typescript
interface PonyModel {
  name: string;
  speed: number;
}

const pony: PonyModel = { name: 'Light Shoe', speed: 56 };

```

### 4.5. Необязательные аргументы

Ещё одна особенность JavaScript заключается в том, что аргументы функций всегда необязательны. Если их не передать, они просто получат значение `undefined`. Но если вы определите функцию с типизированными параметрами в TypeScript, компилятор выдаст ошибку, если вы забудете их передать:

```typescript
addPointsToScore(player); 
// Ошибка TS2346: Переданные параметры не соответствуют ни одной сигнатуре вызова.

```

Чтобы сделать параметр функции (или свойство интерфейса) необязательным, достаточно добавить знак `?` после его имени. В данном случае параметр `points` можно сделать необязательным:

```typescript
function addPointsToScore(player: HasScore, points?: number): void {
  points = points || 0;
  player.score += points;
}

```

### 4.6. Функции как свойства

Вам также может потребоваться описать параметр, который должен содержать конкретную функцию, а не просто свойство-значение.

Определение интерфейса в таком случае выглядит так:

```typescript
interface CanRun {
  run(meters: number): void;
}

function startRunning(pony: CanRun): void {
  pony.run(10);
}

const ponyOne = {
  run: (meters: number) => logger.log(`pony runs ${meters}m`)
};

startRunning(ponyOne);

```

### 4.7. Классы

Класс может реализовывать интерфейс. Например, если наш класс `Pony` должен уметь бегать, мы можем написать:

```typescript
class Pony implements CanRun {
  run(meters: number): void {
    logger.log(`pony runs ${meters}m`);
  }
}

```

Компилятор заставит нас реализовать метод `run` внутри класса. Если мы реализуем его некорректно (например, ожидем `string` вместо `number`), компилятор выдаст ошибку:

```typescript
class IllegalPony implements CanRun {
  run(meters: string) {
    console.log(`pony runs ${meters}m`);
  }
}
// Ошибка TS2420: Класс 'IllegalPony' некорректно реализует интерфейс 'CanRun'.
// Типы свойства 'run' несовместимы.

```

При желании класс может реализовывать сразу несколько интерфейсов:

```typescript
class HungryPony implements CanRun, CanEat {
  run(meters: number): void {
    logger.log(`pony runs ${meters}m`);
  }

  eat(): void {
    logger.log(`pony eats`);
  }
}

```

А сам интерфейс может расширять один или несколько других интерфейсов:

```typescript
interface Animal extends CanRun, CanEat {}

class Pony implements Animal {
  // ...
}

```

При определении класса в TypeScript вы можете объявлять свойства напрямую в теле класса. Явное объявление свойств классов не является стандартной фичей ES2015+ — в таком виде это возможно только благодаря TypeScript.

```typescript
class SpeedyPony {
  speed = 10;

  run(): void {
    logger.log(`pony runs at ${this.speed}m/s`);
  }
}

```

По умолчанию все свойства и методы публичны (`public`), но вы можете использовать ключевое слово `private`, чтобы скрыть их.

Если добавить `private` или `public` прямо к параметрам конструктора, это сработает как сокращенная запись для автоматического создания и инициализации полей класса:

```typescript
class NamedPony {
  constructor(
    public name: string,
    private speed: number
  ) {}

  run(): void {
    logger.log(`pony runs at ${this.speed}m/s`);
  }
}

const pony = new NamedPony('Rainbow Dash', 10);
// Создает публичное свойство 'name' со значением 'Rainbow Dash'
// и приватное свойство 'speed' со значением 10

```

Это абсолютно эквивалентно более громоздкой записи:

```typescript
class NamedPonyWithoutShortcut {
  public name: string;
  private speed: number;

  constructor(name: string, speed: number) {
    this.name = name;
    this.speed = speed;
  }

  run(): void {
    logger.log(`pony runs at ${this.speed}m/s`);
  }
}

```

Эти синтаксические сокращения крайне удобны, и мы будем очень часто опираться на них в Angular!

### 4.8. Работа со сторонними библиотеками

При работе со сторонними JS-библиотеками может показаться, что мы зашли в тупик, ведь компилятор не знает, какие типы параметров ждут их функции. В этом и заключается одно из главных преимуществ сообщества TypeScript: энтузиасты описали интерфейсы для типов и функций большинства популярных JavaScript-библиотек!

Файлы с такими интерфейсами имеют специальное расширение `.d.ts`. Они содержат список публичных функций библиотеки. Отличное место для поиска таких типов — репозиторий **DefinitelyTyped**. Например, если вы хотите использовать TS в проекте на AngularJS 1.x, вы можете установить готовые типы через NPM:

```bash
npm install --save-dev @types/angular

```

или скачать их вручную.

Затем добавьте указание на файл в начале вашего кода и пользуйтесь проверкой типов при компиляции:

```typescript
/// <reference path="angular.d.ts" />
angular.module(10, []); // Имя модуля должно быть строкой!
// При компиляции получим:
// Argument of type 'number' is not assignable to parameter of type 'string'.

```

Специальный комментарий `/// <reference path="angular.d.ts" />` указывает компилятору TS искать интерфейсы в файле `angular.d.ts`.

Если вы некорректно вызовете метод AngularJS, компилятор сразу же сообщит об ошибке, и вы сможете исправить её прямо на месте, не запуская приложение вручную!

Более того, начиная с TypeScript 1.6, компилятор умеет автоматически находить определения типов внутри самих NPM-пакетов, если они поставляются вместе с библиотекой. Всё больше проектов переходят на этот подход, включая сам Angular. Поэтому вам даже не придется переживать о ручном подключении интерфейсов: компилятор TS сделает всё сам, если вы используете NPM для управления зависимостями!

### 4.9. Декораторы

Эта возможность была добавлена в TypeScript 1.5 специально для поддержки Angular. Действительно, как мы скоро увидим, компоненты Angular описываются именно с помощью декораторов.

Возможно, вы раньше не сталкивались с декораторами, так как они есть далеко не во всех языках. Декоратор — это способ метапрограммирования. Они очень похожи на аннотации, применяемые в Java, C#, Python и некоторых других языках.

Как правило, аннотации не используются самим языком — они нужны фреймворкам и библиотекам. Декораторы крайне мощны: они могут модифицировать целевой объект (метод, класс и т.д.), изменять передаваемые параметры, подменять результат работы, вызывать дополнительные методы или добавлять метаданные для фреймворка (именно это и делают декораторы в Angular).

Со времени их появления в TypeScript сам JavaScript развился и теперь поддерживает декораторы нативно.

В Angular мы будем использовать декораторы, предоставляемые фреймворком. Их роль достаточно проста: они добавляют к нашим классам, атрибутам или параметрам метаданные вроде *«этот класс является компонентом»*, *«это внедряемый сервис»* и т.д. Вы не обязаны их использовать и можете прописывать метаданные вручную (например, если решите остаться на ES5), но с декораторами TypeScript код выглядит несравнимо элегантнее.

В TypeScript декораторы начинаются со символа `@` и могут применяться к классам, свойствам классов, функциям или параметрам функций. Их нельзя применять напрямую к конструктору, но можно к его параметрам.

Вот как выглядит декоратор в Angular на практике:

```typescript
@Component({ selector: 'ns-home', template: 'home' })
class Home {
  // ...
}

```

Декоратор `@Component` применяется к классу `Home`. Когда Angular загружает наше приложение, он находит класс `Home` и понимает, что это компонент, считывая метаданные, добавленные декоратором.

Круто, правда? Как видите, декоратор также может принимать параметры — в данном случае объект конфигурации.

Это было краткое введение в концепцию декораторов; подробно с каждым доступным в Angular декоратором мы познакомимся далее в книге.

TypeScript незаменим для Angular-разработчиков, но он также стал стандартом де-факто во всей экосистеме JavaScript. Независимо от разрабатываемого приложения, наличие типов делает код более надежным, читаемым и поддерживаемым.

Все последующие примеры в книге будут приведены на TypeScript.

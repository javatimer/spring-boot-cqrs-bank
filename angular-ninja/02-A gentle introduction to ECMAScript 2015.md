Да. И здесь я предлагаю идти **не всей главой одним огромным куском**, а примерно по 3–4 подраздела за раз — глава 2 довольно большая. В этом фрагменте книги идут `let`, `const`, shorthand-синтаксис, destructuring, default parameters, rest/spread, classes и дальше Promises/arrow functions. 

# Глава 2. Небольшое введение в ECMAScript 2015+

Если ты читаешь эту книгу, можно с уверенностью предположить, что ты слышал о JavaScript.

То, что мы называем **JS**, — это одна из реализаций стандартной спецификации под названием **ECMAScript**.

Версия спецификации, с которой большинство из нас знакомо лучше всего, — это версия 5, которая использовалась на протяжении многих лет.

Но в 2015 году появилась новая версия спецификации — **ECMAScript 2015**, или **ES2015**. Её также иногда называют **ES6**, поскольку это была шестая версия спецификации.

С тех пор новая версия спецификации выходит каждый год: ES2016, ES2017 и так далее. Каждый год в язык добавляется несколько новых возможностей.

Дальше я в основном буду говорить **ES2015**, поскольку это наиболее распространённое название, либо **ES2015+**, когда речь идёт сразу об ES2015, ES2016, ES2017 и последующих версиях.

ES2015 добавил в JavaScript **огромное количество новых возможностей**: классы, константы, стрелочные функции, генераторы и многое другое.

Всего настолько много, что мы не сможем рассмотреть здесь всё — на это потребовалась бы целая книга.

Но Angular создавался с расчётом на использование новой версии JavaScript.

И хотя ты всё ещё можешь писать приложения на старом JavaScript, использование ES2015+ сделает разработку гораздо приятнее.

Поэтому в этой главе мы немного разберёмся с ES2015+ и посмотрим, какие возможности пригодятся нам при создании Angular-приложений. 

Мы намеренно оставим множество вещей за рамками и не будем пытаться охватить всё оставшееся.

Но это будет отличной отправной точкой.

Если ты уже хорошо знаешь ES2015+, можешь пропустить эти страницы.

А если нет — ты узнаешь несколько действительно замечательных вещей, которые пригодятся тебе даже в том случае, если в будущем ты вообще не будешь использовать Angular.

# 2.1. Транспиляторы

Шестая версия спецификации достигла окончательного состояния в 2015 году.

Сегодня её поддерживают современные браузеры, но в мире всё ещё существуют браузеры, которые либо вообще не поддерживают её, либо поддерживают только частично.

А теперь, когда новая спецификация выходит каждый год — ES2016, ES2017 и так далее, — некоторые браузеры всегда будут отставать.

Ты можешь спросить:

> «А какой тогда во всём этом смысл, если мне всё равно приходится следить за тем, что я могу использовать?»

И это вполне справедливый вопрос, потому что не так уж много приложений могут позволить себе полностью игнорировать старые браузеры.

Но поскольку практически каждый JavaScript-разработчик, попробовавший ES2015+, хочет писать приложения на ES2015+, сообщество нашло решение: **транспилятор**. 

Транспилятор берёт исходный код ES2015+ и генерирует код ES5, который может выполняться в браузерах.

Он также генерирует **source map-файлы**, благодаря которым в браузере можно отлаживать непосредственно исходный код ES2015+.

В 2015 году существовали две основные альтернативы для транспиляции ES2015+:

* **Traceur** — проект Google, исторически появившийся первым, но сейчас уже не поддерживаемый.
* **Babel** — проект, начатый молодым разработчиком Себастьяном Маккензи (ему тогда было 17 лет — да, это заставляет меня чувствовать себя старым), а затем получивший огромное количество вкладов от сообщества. 

Сам исходный код Angular сначала транспилировался с помощью **Traceur**, но затем команда перешла на **TypeScript**.

TypeScript — это open-source язык, разработанный Microsoft.

Это **типизированное расширение JavaScript**, которое компилируется в обычный JavaScript. Но совсем скоро мы разберём TypeScript подробнее.

Если говорить честно, сегодня у Babel гораздо больше популярности, чем у Traceur, поэтому я бы рекомендовал использовать именно его.

По сути, Babel стал де-факто стандартом в этой области. 

Так что если ты хочешь поэкспериментировать с ES2015+ или подключить его в одном из своих проектов, посмотри на транспиляторы и добавь соответствующий шаг в процесс сборки.

Он возьмёт исходные файлы ES2015+ и создаст эквивалентный код ES5.

Работает это очень хорошо, хотя некоторые новые возможности довольно сложно или вообще невозможно преобразовать в ES5 — просто потому, что в ES5 их изначально не существовало.

Тем не менее современное состояние инструментов вполне позволяет использовать ES2015+ без особых переживаний.

Так что давай посмотрим, какие замечательные новые возможности появились в JavaScript!

# 2.2. `let`

Если ты какое-то время писал на JS, то знаешь, что объявление переменных через `var` может быть довольно хитрым.

Практически в любом другом языке переменная объявляется там, где находится её объявление.

Но в JavaScript существует концепция под названием **hoisting** — «всплытие» объявлений.

Она приводит к тому, что переменная фактически объявляется в начале функции, даже если в исходном коде её объявление находится гораздо ниже. 

Например:

```javascript
function getPonyFullName(pony) {
  if (pony.isChampion) {
    var name = 'Champion ' + pony.name;
    return name;
  }
  return pony.name;
}
```

Фактически это эквивалентно объявлению переменной в начале функции:

```javascript
function getPonyFullName(pony) {
  var name;
  if (pony.isChampion) {
    name = 'Champion ' + pony.name;
    return name;
  }
  // name всё ещё доступна здесь
  return pony.name;
}
```

ES2015 вводит новое ключевое слово для объявления переменных — **`let`**.

Оно ведёт себя гораздо более ожидаемо:

```javascript
function getPonyFullName(pony) {
  if (pony.isChampion) {
    let name = 'Champion ' + pony.name;
    return name;
  }
  // name здесь недоступна
  return pony.name;
}
```

Теперь переменная `name` ограничена **областью видимости блока**.

`let` был введён как замена `var` в долгосрочной перспективе, поэтому старый добрый `var` можно практически забыть и начать использовать `let`.

Самое приятное, что переход на `let` должен быть практически безболезненным.

А если он не получается без проблем — возможно, ты как раз обнаружил какую-то проблему в своём коде. 😄

# 2.3. Константы

Раз уж мы заговорили о новых ключевых словах и переменных, есть ещё одно, которое стоит знать.

ES2015 добавляет `const` для объявления...

**констант!**

При объявлении переменной через `const` её необходимо сразу инициализировать, и впоследствии нельзя присвоить ей другое значение:

```javascript
const poniesInRace = 6;
```

А это вызовет ошибку:

```javascript
poniesInRace = 7; // SyntaxError
```

Как и переменные, объявленные через `let`, константы не подвергаются hoisting и имеют область видимости уровня блока. 

Но здесь есть один момент, который может удивить.

Можно создать `const`, содержащий объект, а затем изменить **содержимое объекта**:

```javascript
const PONY = {};
PONY.color = 'blue'; // работает
```

Но нельзя присвоить самой константе другой объект:

```javascript
const PONY = {};
```

```javascript
PONY = {color: 'blue'}; // SyntaxError
```

То же самое относится к массивам:

```javascript
const PONIES = [];
PONIES.push({ color: 'blue' }); // работает
```

Но:

```javascript
PONIES = []; // SyntaxError
```

То есть `const` запрещает **переприсваивание самой переменной**, а не делает объект внутри неё неизменяемым.

# 2.4. Сокращённый синтаксис создания объектов

Это не новое ключевое слово, но такая возможность тоже может привлечь внимание при чтении кода ES2015.

Теперь существует сокращённый синтаксис создания объектов, когда имя свойства совпадает с именем переменной, значение которой мы хотим туда поместить.

Например, раньше:

```javascript
function createPony() {
  const name = 'Rainbow Dash';
  const color = 'blue';
  return { name: name, color: color };
}
```

можно написать короче:

```javascript
function createPony() {
  const name = 'Rainbow Dash';
  const color = 'blue';
  return { name, color };
}
```

То есть JavaScript понимает:

```javascript
{ name }
```

как:

```javascript
{ name: name }
```

То же самое относится к методам объекта.

Вместо:

```javascript
function createPony() {
  return {
    run: () => {
      console.log('Run!');
    }
  };
}
```

можно написать:

```javascript
function createPony() {
  return {
    run() {
      console.log('Run!');
    }
  };
}
```

Такой синтаксис особенно часто встретится нам в современном TypeScript и Angular.

# 2.5. Деструктуризация

Ещё одна очень важная возможность ES2015 — **destructuring assignment**, или **деструктуризация**.

Она позволяет удобно извлекать значения из объектов и массивов и присваивать их переменным.

В ES5 мы могли написать:

```javascript
var httpOptions = { timeout: 2000, isCache: true };
// later
var httpTimeout = httpOptions.timeout;
var httpCache = httpOptions.isCache;
```

В ES2015 можно сделать так:

```javascript
const httpOptions = { timeout: 2000, isCache: true };
// later
const { timeout: httpTimeout, isCache: httpCache } = httpOptions;
```

Результат тот же.

Поначалу синтаксис может показаться немного странным:

```javascript
const { timeout: httpTimeout } = httpOptions;
```

Здесь `timeout` — это **имя свойства объекта**, а `httpTimeout` — **имя переменной**, в которую мы помещаем значение. 

Но если имя переменной совпадает с именем свойства, всё становится ещё проще:

```javascript
const httpOptions = { timeout: 2000, isCache: true };
// later
const { timeout, isCache } = httpOptions;
```

Теперь у нас есть переменная `timeout` и переменная `isCache` с соответствующими значениями.

Деструктуризация работает и с вложенными объектами:

```javascript
const httpOptions = { timeout: 2000, cache: { age: 2 } };
// later
const {
  cache: { age }
} = httpOptions;
// you now have a variable named 'age' with value 2
```

И, конечно, с массивами:

```javascript
const timeouts = [1000, 2000, 3000];
// later
const [shortTimeout, mediumTimeout] = timeouts;
```

Получаем:

* `shortTimeout = 1000`
* `mediumTimeout = 2000`

Она также работает с вложенными массивами, массивами внутри объектов, объектами внутри массивов и так далее. 

### Особенно полезный случай

Деструктуризация отлично подходит для функций, возвращающих несколько значений.

Представим функцию `randomPonyInRace`, которая возвращает пони и его позицию в гонке:

```javascript
function randomPonyInRace() {
  const pony = { name: 'Rainbow Dash' };
  const position = 2;
  // ...
  return { pony, position };
}

const { position, pony } = randomPonyInRace();
```

Деструктуризация автоматически положит `position` в переменную `position`, а `pony` — в переменную `pony`.

А если позиция нам вообще не нужна:

```javascript
const { pony } = randomPonyInRace();
```

И всё — у нас будет только `pony`.

### 2.6. Параметры и значения по умолчанию

Одной из особенностей JavaScript является то, что он позволяет разработчикам вызывать функцию с любым количеством аргументов:

* если вы передадите больше аргументов, чем количество параметров, лишние аргументы будут проигнорированы (строго говоря, вы всё ещё можете использовать их через специальную переменную `arguments`);
* если вы передадите меньше аргументов, чем количество параметров, отсутствующему параметру будет присвоено значение `undefined`.

Последний случай представляет для нас наибольший интерес. Обычно мы передаем меньше аргументов, когда параметры являются необязательными, как в следующем примере:

```javascript
function getPonies(size, page) {
  size = size || 10;
  page = page || 1;
  // ...
  server.get(size, page);
}

```

Необязательные параметры обычно имеют значение по умолчанию. Оператор **ИЛИ** (`||`) возвращает правый операнд, если левый равен `undefined` — что и происходит, когда параметр не был передан (если быть предельно точным, когда он является ложным / *falsy*, т.е. `0`, `false`, `""` и т.д.).

С помощью этой хитрости функцию `getPonies` можно вызывать следующим образом:

```javascript
getPonies(20, 2);
getPonies(); // то же самое, что и getPonies(10, 1);
getPonies(15); // то же самое, что и getPonies(15, 1);

```

Это работало нормально, но без чтения тела функции было не совсем очевидно, что параметры являются необязательными и имеют значения по умолчанию.

В ES2015 появился более точный способ задания параметров по умолчанию — непосредственно в объявлении функции:

```javascript
function getPonies(size = 10, page = 1) {
  // ...
  server.get(size, page);
}

```

Теперь совершенно понятно, что параметр `size` будет равен `10`, а `page` — `1`, если они не будут переданы.

Однако есть небольшое отличие: теперь `0` или `""` являются валидными значениями и не будут заменены на значение по умолчанию, как это сделала бы конструкция `size = size || 10`. Это работает скорее как `size = size === undefined ? 10 : size;`.

Значением по умолчанию также может быть вызов функции:

```javascript
function getPonies(size = defaultSize(), page = 1) {
  // метод defaultSize будет вызван, если параметр size не передан
  // ...
  server.get(size, page);
}

```

или даже другие переменные — как глобальные, так и другие параметры функции:

```javascript
function getPonies(size = defaultSize(), page = size - 1) {
  // если параметр page не передан, ему будет присвоено значение
  // параметра size минус единица.
  // ...
  server.get(size, page);
}

```

Этот механизм параметров также можно применять к значениям, например, при использовании деструктурирующего присваивания:

```javascript
const { timeout = 1000 } = httpOptions;
// теперь у вас есть переменная 'timeout',
// со значением 'httpOptions.timeout', если оно существует,
// или 1000, если его нет

```

### 2.7. Rest-оператор (Оператор остатка)

В ES2015 появился новый синтаксис для определения функций с переменным числом параметров.

Как упоминалось в предыдущей части, вы всегда могли передавать функции дополнительные аргументы и получать их с помощью специальной переменной `arguments`. Таким образом, вы могли написать что-то вроде этого:

```javascript
function addPonies(ponies) {
  for (var i = 0; i < arguments.length; i++) {
    poniesInRace.push(arguments[i]);
  }
}

addPonies('Rainbow Dash', 'Pinkie Pie');

```

Но, думаю, мы согласимся, что это выглядит не очень красиво и не совсем очевидно: поскольку параметр `ponies` нигде не используется, откуда нам знать, что можно передать несколько пони?

ES2015 предлагает гораздо более удачный синтаксис с использованием rest-оператора `...`:

```javascript
function addPonies(...ponies) {
  for (const pony of ponies) {
    poniesInRace.push(pony);
  }
}

```

Теперь `ponies` — это настоящий массив, по которому мы можем итерироваться.

Цикл `for ... of`, используемый для итерации, также является новой фичей ES2015. Он гарантирует, что вы обходите именно *значения* коллекции, а не ее свойства, как это сделал бы цикл `for ... in`.

Разве наш код не стал выглядеть симпатичнее и понятнее?

Rest-оператор также работает и при деструктуризации данных:

```javascript
const [winner, ...losers] = poniesInRace;
// предполагая, что 'poniesInRace' — это массив с несколькими пони:
// 'winner' получит первого пони,
// а 'losers' станет массивом из всех остальных

```

Rest-оператор не следует путать со **spread-оператором** (оператором расширения), который, надо признать, выглядит ужасно похоже! Но spread-оператор делает противоположное: он берет массив и "разворачивает" его в отдельные аргументы.

Единственные примеры, которые приходят на ум — это функции вроде `Math.min` или `Math.max`, которые принимают переменное количество аргументов и которые вам может потребоваться вызвать для массива:

```javascript
const ponyPrices = [12, 3, 4];
const minPrice = Math.min(...ponyPrices);

```

### 2.8. Классы

Одна из самых знаковых новых возможностей, которую мы будем активно использовать при написании приложений на Angular: ES2015 вводит классы в JavaScript!

Теперь вы можете легко использовать классы и наследование в JS. Вы могли делать это и раньше, используя прототипное наследование, но это была непростая задача, особенно для новичков.

Теперь всё очень просто, взгляните:

```javascript
class Pony {
  constructor(color) {
    this.color = color;
  }

  toString() {
    return `${this.color} pony`;
    // Видите это? Это ещё одна крутая фича ES2015, называемая шаблонными строками.
    // Мы скоро о них поговорим!
  }
}

const bluePony = new Pony('blue');
console.log(bluePony.toString()); // blue pony

```

Объявления классов, в отличие от объявлений функций, **не подтягиваются** (not hoisted), поэтому вам нужно объявить класс перед его использованием.

Возможно, вы заметили специальную функцию `constructor`. Это функция, которая вызывается при создании нового объекта Pony с помощью оператора `new`. В данном случае ей требуется цвет, и мы создаем новый экземпляр `Pony` с цветом `"blue"`.

Класс также может иметь методы, вызываемые у экземпляра, как метод `toString()` в примере выше.

Он также может иметь статические атрибуты и методы:

```javascript
class Pony {
  static defaultSpeed() {
    return 10;
  }
}

```

Статические методы можно вызывать только напрямую у самого класса:

```javascript
const speed = Pony.defaultSpeed();

```

Класс может иметь геттеры и сеттеры, если вы хотите перехватывать эти операции:

```javascript
class Pony {
  get color() {
    console.log('get color');
    return this._color;
  }

  set color(newColor) {
    console.log(`set color ${newColor}`);
    this._color = newColor;
  }
}

const pony = new Pony();
pony.color = 'red'; // 'set color red'
console.log(pony.color); // 'get color', затем 'red'

```

И, конечно же, раз у вас есть классы, в ES2015 из коробки доступно и наследование.

```javascript
class Animal {
  speed() {
    return 10;
  }
}

class Pony extends Animal {}

const pony = new Pony();
console.log(pony.speed()); // 10, так как Pony наследует метод родителя

```

`Animal` называется базовым классом, а `Pony` — производным классом.
Как видите, производный класс имеет методы базового класса. Он также может их переопределять:

```javascript
class Animal {
  speed() {
    return 10;
  }
}

class Pony extends Animal {
  speed() {
    return super.speed() + 10;
  }
}

const pony = new Pony();
console.log(pony.speed()); // 20, так как Pony переопределяет метод родителя

```

Как видите, ключевое слово `super` позволяет вызывать метод базового класса (например, `super.speed()`).
Ключевое слово `super` также можно использовать в конструкторах для вызова конструктора базового класса:

```javascript
class Animal {
  constructor(speed) {
    this.speed = speed;
  }
}

class Pony extends Animal {
  constructor(speed, color) {
    super(speed);
    this.color = color;
  }
}

const pony = new Pony(20, 'blue');
console.log(pony.speed); // 20

```

### 2.9. Промисы (Promises)

Промисы не так уж новы, и вы, возможно, уже знаете или используете их, так как они составляли важную часть AngularJS 1.x. Но поскольку вы будете часто использовать их в Angular (да и вообще при разработке на JS), я считаю важным сделать на них остановку.

Промисы предназначены для упрощения асинхронного программирования. Наш код на JS полон асинхронных вещей, таких как AJAX-запросы, и обычно мы используем колбэки (callback) для обработки результата и ошибок. Но это может превратиться в кашу из вложенных друг в друга колбэков, что делает код трудным для чтения и поддержки.

Промисы гораздо удобнее колбэков, так как они делает код "плоским" и, следовательно, более простым для понимания.

Давайте рассмотрим простой пример, где нам нужно получить пользователя, затем его права, а затем обновить меню, когда мы их получим.

С колбэками:

```javascript
getUser(login, function (user) {
  getRights(user, function (rights) {
    updateMenu(rights);
  });
});

```

Теперь давайте сравним это с промисами:

```javascript
getUser(login)
  .then(function (user) {
    return getRights(user);
  })
  .then(function (rights) {
    updateMenu(rights);
  });

```

Мне нравится эта версия, потому что она выполняется ровно так, как читается: Я хочу получить пользователя, *затем* (then) получить его права, *затем* обновить меню.

Как видите, промис — это «thenable» объект, что просто означает наличие у него метода `then`. Этот метод принимает два аргумента: один колбэк успешного выполнения и один колбэк ошибки (отклонения).

Промис имеет три состояния:

1. **pending** (в ожидании): пока промис не завершен (например, наш запрос к серверу еще не выполнен).
2. **fulfilled** (выполнен успешно): когда промис успешно завершился (например, запрос к серверу вернул HTTP-статус OK).
3. **rejected** (отклонен): когда промис завершился с ошибкой (например, сервер вернул статус 404).

Когда промис переходит в состояние *fulfilled*, вызывается колбэк успешного выполнения с результатом в качестве аргумента. Если промис отклонен (*rejected*), вызывается колбэк ошибки с переданной причиной или объектом ошибки.

Итак, как создать промис? Довольно просто: появился новый класс `Promise`, конструктор которого ожидает функцию с двумя параметрами — `resolve` и `reject`.

```javascript
const getUser = function (login) {
  return new Promise(function (resolve, reject) {
    // асинхронные действия, например, получение пользователей с сервера
    if (response.status === 200) {
      resolve(response.data);
    } else {
      reject('No user');
    }
  });
};

```

После создания промиса вы можете зарегистрировать колбэки с помощью метода `then`. Этот метод может принимать два параметра — два колбэка для случаев успеха или ошибки. В данном случае мы передаем только успешный колбэк, игнорируя возможную ошибку:

```javascript
getUser(login)
  .then(function (user) {
    console.log(user);
  });

```

Как только промис разрешится (resolved), будет вызван успешный колбэк (здесь он просто выводит пользователя в консоль).

Самое крутое в том, что это делает код плоским. Например, если ваш колбэк успешного выполнения сам возвращает промис, вы можете написать:

```javascript
getUser(login)
  .then(function (user) {
    return getRights(user) // getRights возвращает промис
      .then(function (rights) {
        return updateMenu(rights);
      });
  });

```

но ещё красивее — вот так:

```javascript
getUser(login)
  .then(function (user) {
    return getRights(user); // getRights возвращает промис
  })
  .then(function (rights) {
    return updateMenu(rights);
  });

```

Ещё один интересный момент — это обработка ошибок. Вы можете использовать один обработчик на каждый промис или один общий для всей цепочки.

По одному на промис:

```javascript
getUser(login)
  .then(
    function (user) {
      return getRights(user);
    },
    function (error) {
      console.log(error); // вызовется, если getUser завершится ошибкой
      return Promise.reject(error);
    }
  )
  .then(
    function (rights) {
      return updateMenu(rights);
    },
    function (error) {
      console.log(error); // вызовется, если getRights завершится ошибкой
      return Promise.reject(error);
    }
  );

```

Один для всей цепочки:

```javascript
getUser(login)
  .then(function (user) {
    return getRights(user);
  })
  .then(function (rights) {
    return updateMenu(rights);
  })
  .catch(function (error) {
    console.log(error); // вызовется, если getUser или getRights завершатся ошибкой
  });

```

Вам действительно стоит внимательно изучить промисы, потому что они становятся стандартным способом написания API, и их будет использовать каждая библиотека. Даже стандартные: например, новый Fetch API работает именно на них.

### 2.10. Стрелочные функции

Что мне очень нравится в ES2015, так это новый синтаксис стрелочных функций с использованием оператора "жирной стрелки" (`=>`). Он НЕВЕРОЯТНО удобен для колбэков и анонимных функций!

Возьмем наш предыдущий пример с промисами:

```javascript
getUser(login)
  .then(function (user) {
    return getRights(user); // getRights возвращает промис
  })
  .then(function (rights) {
    return updateMenu(rights);
  });

```

С использованием стрелочных функций его можно переписать так:

```javascript
getUser(login)
  .then(user => getRights(user))
  .then(rights => updateMenu(rights));

```

Насколько это круто? Невероятно круто!

Обратите внимание, что оператор `return` является неявным, если нет блока кода с фигурными скобками: нет необходимости писать `user => return getRights(user)`.
Но если бы у нас был блок кода, явный `return` всё же потребовался бы:

```javascript
getUser(login)
  .then(user => {
    console.log(user);
    return getRights(user);
  })
  .then(rights => updateMenu(rights));

```

И у стрелочных функций есть одна суперспособность по сравнению с обычными функциями: контекст `this` остается **лексически привязанным** (lexically bounded). Это означает, что у этих функций нет своего собственного `this`, в отличие от других функций.

Давайте рассмотрим пример, где вы итерируетесь по массиву с помощью функции `map` (или `forEach`), чтобы найти максимальное значение.

В ES5:

```javascript
var maxFinder = {
  max: 0,
  find: function (numbers) {
    // итерируемся
    numbers.forEach(function (element) {
      // если элемент больше, устанавливаем его как max
      if (element > this.max) {
        this.max = element;
      }
    });
  }
};

maxFinder.find([2, 3, 4]);
// выводим результат
console.log(maxFinder.max);

```

Вы ожидали бы, что это сработает, но это не так. Если вы внимательны, вы могли заметить, что `forEach` внутри функции `find` использует `this`, но этот `this` не привязан к объекту. Поэтому `this.max` — это не свойство `max` объекта `maxFinder`…

Конечно, вы можете легко исправить это с помощью переменной-псевдонима:

```javascript
var maxFinder = {
  max: 0,
  find: function (numbers) {
    var self = this;
    numbers.forEach(function (element) {
      if (element > self.max) {
        self.max = element;
      }
    });
  }
};

maxFinder.find([2, 3, 4]);
console.log(maxFinder.max);

```

или привязав `this` явно с помощью `.bind()`:

```javascript
var maxFinder = {
  max: 0,
  find: function (numbers) {
    numbers.forEach(
      function (element) {
        if (element > this.max) {
          this.max = element;
        }
      }.bind(this)
    );
  }
};

maxFinder.find([2, 3, 4]);
console.log(maxFinder.max);

```

или даже передав `this` вторым параметром в функцию `forEach` (как это и было задумано):

```javascript
var maxFinder = {
  max: 0,
  find: function (numbers) {
    numbers.forEach(function (element) {
      if (element > this.max) {
        this.max = element;
      }
    }, this);
  }
};

maxFinder.find([2, 3, 4]);
console.log(maxFinder.max);

```

Но теперь есть куда более изящное решение благодаря синтаксису стрелочных функций:

```javascript
const maxFinder = {
  max: 0,
  find: function (numbers) {
    numbers.forEach(element => {
      if (element > this.max) {
        this.max = element;
      }
    });
  }
};

maxFinder.find([2, 3, 4]);
console.log(maxFinder.max);

```

Это делает стрелочные функции идеальными кандидатами на роль анонимных функций в колбэках!

### 2.11. Async/await

Ранее мы говорили о промисах, и стоит знать, что для работы с ними в более синхронном стиле было introduced ещё одно ключевое слово: `await`.

Эта фича появилось не в ECMAScript 2015, а в ECMAScript 2017. Чтобы использовать `await`, ваша функция должна быть помечена ключевым словом `async`.

Когда вы используете `await` перед `Promise`, вы приостанавливаете выполнение вашей `async`-функции, ждете разрешения промиса, а затем возобновляете выполнение. Возвращаемое значение будет сгенерировано разрешенным промисом.

Таким образом, мы можем переписать наш предыдущий пример с использованием `async/await` вот так:

```javascript
async function getUserRightsAndUpdateMenu() {
  // getUser возвращает промис
  const user = await getUser(login);
  // getRights возвращает промис
  const rights = await getRights(user);
  updateMenu(rights);
}

await getUserRightsAndUpdateMenu();

```

И ваш код теперь выглядит так, будто он синхронный!

Ещё одна крутая фича `async/await` заключается в том, что вы можете использовать обычные блоки `try/catch` для обработки ошибок:

```javascript
async function getUserRightsAndUpdateMenu() {
  try {
    // getUser возвращает промис
    const user = await getUser(login);
    // getRights возвращает промис
    const rights = await getRights(user);
    updateMenu(rights);
  } catch (e) {
    // вызовется, если getUser, getRights или updateMenu завершатся ошибкой
    console.log(e);
  }
}

await getUserRightsAndUpdateMenu();

```

Обратите внимание: несмотря на то, что код с `async/await` выглядит синхронным, он всё равно остается асинхронным. Выполнение функции приостанавливается и возобновляется, но, как и в случае с колбэками, это не блокирует главный поток execution: пока выполнение приостановлено, могут обрабатываться другие события JavaScript.

### 2.12. Set и Map

Короткий раздел: теперь в ES2015 есть полноценные коллекции.
Ура \o/! Раньше мы использовали объекты-словари в роли карт (map), но теперь мы можем использовать специальный класс `Map`:

```javascript
const cedric = { id: 1, name: 'Cedric' };
const users = new Map();

users.set(cedric.id, cedric); // добавляет пользователя
console.log(users.has(cedric.id)); // true
console.log(users.size); // 1
users.delete(cedric.id); // удаляет пользователя

```

У нас также есть класс `Set`:

```javascript
const cedric = { id: 1, name: 'Cedric' };
const users = new Set();

users.add(cedric); // добавляет пользователя
console.log(users.has(cedric)); // true
console.log(users.size); // 1
users.delete(cedric); // удаляет пользователя

```

Вы можете итерироваться по коллекции с помощью нового синтаксиса `for ... of`:

```javascript
for (const user of users) {
  console.log(user.name);
}

```

Вы увидите, что синтаксис `for ... of` — это то, что команда Angular выбрала для итерации по коллекциям в шаблонах.

### 2.13. Шаблонные строки (Template literals)

Составление строк всегда было мучением в JavaScript, так как обычно нам приходилось использовать конкатенацию:

```javascript
const fullname = 'Miss ' + firstname + ' ' + lastname;

```

Шаблонные строки — это новая небольшая возможность, где вам нужно использовать обратные кавычки (```) вместо обычных одинарных или двойных кавычек. Вы получаете базовую систему шаблонов с поддержкой многострочности:

```javascript
const fullname = `Miss ${firstname} ${lastname}`;

```

Поддержка многострочности особенно здорово помогает при написании HTML-строк, что мы и будем делать для наших Angular-компонентов:

```javascript
const template = `<div>
  <h1>Hello</h1>
</div>`;

```

И последняя фича — возможность тегирования строк. Вы можете определить функцию и применить ее к шаблонной строке. Здесь `askQuestion` добавляет вопросительный знак в конец строки:

```javascript
const askQuestion = strings => strings + '?';
const template = askQuestion`Hello there`;

```

В чём же разница с обычной функцией?
Тегирующая функция на самом деле получает несколько аргументов:

1. Массив статических частей строки.
2. Значения, полученные в результате вычисления выражений.

Например, если у нас есть шаблонная строка, содержащая выражения:

```javascript
const person1 = 'Cedric';
const person2 = 'Agnes';
const template = `Hello ${person1}! Where is ${person2}?`;

```

то тегирующая функция получит различные статические и динамические части.
Вот тегирующая функция для перевода имен персонажей в верхний регистр:

```javascript
const uppercaseNames = (strings, ...values) => {
  // `strings` — это массив со статическими частями: ['Hello ', '! Where is ', '?']
  // `values` — это массив с вычисленными выражениями: ['Cedric', 'Agnes']
  const names = values.map(name => name.toUpperCase());
  // `names` теперь содержит ['CEDRIC', 'AGNES']
  // давайте объединим массивы `strings` и `names`
  return strings.map((string, i) => `${string}${names[i] ? names[i] : ''}`).join('');
};

const result = uppercaseNames`Hello ${person1}! Where is ${person2}?`;
// возвращает 'Hello CEDRIC! Where is AGNES?'

```

Теперь давайте поговорим об одном из самых больших изменений: модулях.

### 2.14. Модули

В JS всегда не хватало стандартного способа организации функций в пространства имен (namespaces) и динамической загрузки кода.

Node.js был одним из лидеров в этом направлении со своей процветающей экосистемой модулей, использующих конвенцию CommonJS. На стороне браузера также существовал API AMD (Asynchronous Module Definition), используемый RequireJS. Но ни один из них не был настоящим стандартом, что приводило к бесконечным спорам о том, что лучше.

ES2015 стремится создать синтаксис, взяв лучшее из обоих миров, абстрагируясь от конкретной реализации.

Комитет Ecma TC39 (который отвечает за развитие ES2015 и составление спецификации языка) хотел получить красивый и простой синтаксис (что, пожалуй, сильная сторона CommonJS), но при этом поддержать асинхронную загрузку (как в AMD) и некоторые приятные бонусы вроде возможности статического анализа кода инструментами и хорошей поддержки цикличных зависимостей.

Новый синтаксис определяет, как вы экспортируете и импортируете сущности в модули и из них. Модульность действительно важна в Angular, так как практически всё определяется в модулях, которые вам приходится импортировать при необходимости.

Допустим, я хочу предоставить функцию для ставки на конкретного пони в гонке и функцию для старта гонки.

В `races-service.js`:

```javascript
export function bet(race, pony) {
  // ...
}

export function start(race) {
  // ...
}

```

Как видите, это довольно просто: новое ключевое слово `export` делает прозрачную работу и экспортирует две функции.

Теперь предположим, что одному из компонентов нашего приложения нужно вызвать эти функции. В другом файле:

```javascript
import { bet, start } from './races-service';

// позже
bet(race, pony1);
start(race);

```

Это то, что называется **именованным экспортом** (named export). Здесь мы импортируем две функции и должны указать имя файла, содержащего эти функции (в данном случае `'races-service'`).

Конечно, вы можете импортировать только один метод, если вам нужно, и даже дать ему псевдоним (alias):

```javascript
import { start as startRace } from './races-service';

// позже
startRace(race);

```

И если вы хотите использовать все экспортированные символы (функции, константы, классы и т.д.) из модуля, вы можете использовать символ подстановки `*`.

Как и в других языках программирования, используйте `*` с осторожностью — только тогда, когда вам действительно нужны все функции или большинство из них. Поскольку код анализируется нашими IDE, скоро мы увидим автоимпорт, который освободит нас от забот по ручному импорту нужных вещей.

При использовании `*` вы должны дать импорту псевдоним, и мне это даже нравится, так как это делает остальную часть кода clearer (понятнее):

```javascript
import * as racesService from './races-service';

// позже
racesService.bet(race, pony1);
racesService.start(race);

```

Если ваш модуль экспортирует только одну функцию, значение или класс, вам не обязательно использовать именованный экспорт — вы можете задействовать ключевое слово `default`. Это отлично работает, например, для классов:

```javascript
// pony.js
export default class Pony {}

// races-service.js
import Pony from './pony';

```

Обратите внимание на отсутствие фигурных скобок при импорте дефолтного экспорта (`default`). Вы можете импортировать его под любым псевдонимом, но для сохранения последовательности лучше называть импорт именем модуля (за исключением ситуаций, когда у вас есть несколько модулей с одинаковыми именами).

И, конечно же, вы можете смешивать экспорт по умолчанию с именованными экспортами, но, очевидно, только с одним `default` на модуль.

В Angular вы будете постоянно использовать эти импорты. Каждый компонент и сервис будет представлять собой класс, обычно изолированный в собственном файле и экспортируемый, а затем импортируемый по мере необходимости в другие компоненты.

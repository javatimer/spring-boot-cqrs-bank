### Реактивное программирование

#### 16.1. Введение

Основной принцип реактивного программирования заключается в декларативном описании логики: вместо последовательного (императивного) выполнения инструкций мы объявляем события и задаем правила реакции на них.

##### Императивный vs. Реактивный подход

Разберем простой пример. Представьте круг, у которого нужно хранить радиус и радиус окружности (длину окружности). При изменении радиуса длина окружности должна автоматически пересчитываться.

**Императивный подход:**

```typescript
private radius = 0;
private circumference = 0;

setRadius(r: number) {
  this.radius = r;
  this.circumference = 2 * Math.PI * r;
}

```

*Минус:* Каждый раз при изменении радиуса мы обязаны вручную помнить о пересчете длины окружности.

**Реактивный подход (на сигналах):**

```typescript
private readonly radius = signal(0);
private readonly circumference = computed(() => 2 * Math.PI * this.radius());

setRadius(r: number) {
  this.radius.set(r);
}

```

Здесь изменение радиуса рассматривается как событие, а вычисляемый сигнал (`computed`) автоматически реагирует на него.

##### Когда сигналов недостаточно?

Представьте компонент, который получает `raceId` (ID гонки) в качестве `input()` и должен загрузить детали этой гонки с сервера.

Загрузка данных — это **асинхронная операция**. Простой `computed`-сигнал не подходит, так как он рассчитан на синхронные вычисления. Кроме того, возникают дополнительные сложности:

1. Если `raceId` быстро изменился дважды, предыдущий незавершенный HTTP-запрос нужно **отменить**.
2. Если для получения данных требуется сделать два параллельных запроса, нужно дождаться их обоих перед отображением.

Для таких сложных асинхронных сценариев идеальным инструментом является библиотека **RxJS**.

##### RxJS и Angular

RxJS предоставляет базовый реактивный примитив — **Observable** (поток событий), а также множество операторов для трансформации, фильтрации и комбинирования этих потоков.

В Angular наблюдаемые объекты (`Observable`) используются повсеместно:

* Результаты запросов `HttpClient`;
* Изменения параметров роутинга (`ActivatedRoute`);
* Изменения значений реактивных форм (`FormGroup` / `FormControl`).

> **Тренды Angular:** RxJS — мощный, но сложный для освоения инструмент. С появлением сигналов Angular движется в сторону уменьшения жесткой зависимости от RxJS, предоставляя удобный API для **взаимозаменяемости** (*interoperability*) между сигналами и потоками.

#### 16.2. Основы RxJS

`Observable` — это поток событий, обладающий гибким жизненным циклом:

1. При подписке (`subscribe`) он начинает генерировать события (0, 1, несколько или бесконечное количество).
2. Поток может передавать данные как синхронно, так и асинхронно.
3. Поток может **завершиться** (`complete`), после чего подписка автоматически аннулируется.
4. В случае ошибки поток генерирует сигнал `error`, прекращает эмиссию событий и отписывает подписчиков.

##### Пример работы с операторами:

```typescript
import { filter, from, map, Observable } from 'rxjs';

// Суффикс $ — общепринятая конвенция для обозначения переменных-Observable
const numbers$: Observable<number> = from([1, 2, 3, 4, 5]).pipe(
  map(x => x * 2),     // Умножаем каждое число на 2
  filter(x => x > 5)   // Оставляем только числа больше 5
);

numbers$.subscribe(x => console.log(x)); 
// Выведет в консоль: 6, 8, 10

```

##### Обработка пользовательских событий DOM:

```typescript
import { fromEvent } from 'rxjs';

const input = document.querySelector('input')!;

const subscription = fromEvent(input, 'keyup').subscribe(() => console.log('keyup!'));

// Отписка от событий, когда они больше не нужны:
subscription.unsubscribe();

```

##### Полный объект наблюдателя (Observer):

Метод `subscribe()` принимает объект с тремя колбэками: `next`, `error` и `complete`:

```typescript
range(1, 5)
  .pipe(
    map(x => x * 2),
    filter(x => x > 5)
  )
  .subscribe({
    next: x => console.log(x),
    error: err => console.error(err),
    complete: () => console.log('done')
  });
// Выведет: 6, 8, 10, done

```

#### 16.3. Совместимость Сигналов и RxJS (Interoperability)

Как связывать между собой сигналы Angular и потоки RxJS?

Angular предоставляет две функции-конвертера из пакета `@angular/core/rxjs-interop`:

1. **`toObservable()`** — превращает `Signal<T>` в `Observable<T>`.
2. **`toSignal()`** — превращает `Observable<T>` в `Signal<T undefined |>`.

##### Пример: Загрузка данных при изменении входного сигнала

Представим компонент, который отслеживает входной параметр `raceId` и запрашивает данные с сервера:

```typescript
import { Component, inject, input, Signal } from '@angular/core';
import { toObservable, toSignal } from '@angular/core/rxjs-interop';
import { Observable, switchMap } from 'rxjs';

@Component({
  selector: 'ns-race',
  template: '...'
})
export class Race {
  private readonly raceService = inject(RaceService);
  
  // 1. Входной параметр в виде сигнала
  readonly raceId = input.required<number>();

  // 2. Преобразуем сигнал в Observable и обрабатываем с помощью switchMap
  private readonly race$: Observable<RaceModel> = toObservable(this.raceId).pipe(
    switchMap(raceId => this.raceService.get(raceId)) // switchMap отменяет предыдущий запрос при смене raceId
  );

  // 3. Преобразуем итоговый Observable обратно в сигнал для шаблона
  protected readonly race: Signal<RaceModel | undefined> = toSignal(this.race$);
}

```

##### Почему `toSignal` возвращает `Signal<RaceModel undefined |>`?

Так как HTTP-запрос является асинхронным, в момент инициализации компонента данные ещё не получены с сервера. До момента первого ответа от сервера значение сигнала равно `undefined`.

> **Обратите внимание:** Функции `toObservable` и `toSignal` должны вызываться в **контексте внедрения** (*injection context*), то есть при объявлении свойств класса или внутри конструктора, так как под капотом они используют функцию `inject()`. Если вы хотите вызвать их вне контекста внедрения, в параметры параметров необходимо явно передать экземпляр `Injector`.

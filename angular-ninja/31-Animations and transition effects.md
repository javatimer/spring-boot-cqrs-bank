# Анимации и эффекты переходов (Animations and transition effects)

Анимации — это отличное дополнение к любому приложению. Их редко создают в первую очередь, но они способны существенно улучшить пользовательский опыт (UX).

Angular не пытается полностью переизобрести анимации, полагаясь в основном на стандартные возможности CSS. Однако анимация удаления элемента из DOM на чистом CSS всегда была непростой задачей, поэтому Angular предоставляет специальные механизмы для управления появлением и удалением элементов.

Долгое время в фреймворке существовал отдельный пакет `@angular/animations`. Он не опирался напрямую на native CSS и управлял стилями через JavaScript, из-за чего работал менее эффективно. Начиная с версии **Angular 20.2**, пакет `@angular/animations` объявлен устаревшим (**deprecated**). Ему на смену пришел встроенный легкий синтаксис на базе CSS-переходов.

## 31.1. Чистые CSS-анимации

Прежде чем разбирать эффекты переходов при монтировании и размонтировании, рассмотрим базовые CSS-анимации.

Анимации хорошо подходят для привлечения внимания пользователя к определенной области экрана — например, для визуальной индикации невалидности отправленной формы с помощью эффекта тряски («shake») на кнопке.

CSS-анимация опирается на свойство `animation` и директиву `@keyframes`:

**styles.css**

```css
.shaking {
  animation: shake 300ms ease;
}

@keyframes shake {
  10%,
  50%,
  90% {
    transform: translateX(0.5rem);
  }
  30%,
  70% {
    transform: translateX(-0.5rem);
  }
}

```

Как работает этот `@keyframes`:

1. В начале (0%) элемент находится в исходном положении.
2. На 10%, 50% и 90% элемент смещается вправо.
3. На 30% и 70% элемент смещается влево.
4. Браузер автоматически сглаживает промежуточные кадры.
5. На 100% элемент возвращается в исходную позицию.

В Angular этот класс можно динамически добавлять к кнопке при невалидной форме и удалять по завершении анимации с помощью встроенного события `(animationend)`:

**login.html**

```html
<button 
  [class.shaking]="invalidSubmission()" 
  (animationend)="invalidSubmission.set(false)"
>
  Сохранить
</button>

```

**login.ts**

```typescript
protected submit() {
  if (this.form.invalid) {
    this.invalidSubmission.set(true);
    return;
  }
}

```

## 31.2. Переходы появления и исчезновения с animate.enter/animate.leave

CSS-переходы (`transition`) проще анимаций: они описывают плавно происходящее изменение одного или нескольких CSS-свойств элемента.

```css
.pill {
  transition: transform 300ms ease-out;
}

.pill.pill-selected {
  transform: scale(1.1);
}

```

Основная проблема заключается в том, что управляющие конструкции `@if` и `@for` не просто меняют стили, а **физически добавляют или удаляют элементы из DOM**. Обычные CSS-переходы в этот момент не срабатывают без дополнительных ухищрений.

Для решения этой задачи в **Angular v20.2** появился встроенный синтаксис `animate.enter` и `animate.leave`. Он автоматически вешает указанные CSS-классы на элемент в момент его добавления или удаления из DOM, а затем снимает их по завершении анимации.

**example.html**

```html
@if (display()) {
  <div data-testid="content" animate.enter="fade-in" animate.leave="fade-out">
    Контент
  </div>
}

```

Для работы плавной анимации прописываем стили с использованием современного CSS-правила `@starting-style`:

**styles.css**

```css
.fade-in {
  /* Начальное состояние до входа в DOM */
  @starting-style {
    opacity: 0;
  }
  transition: opacity 300ms;
  opacity: 1;
}

.fade-out {
  transition: opacity 300ms;
  opacity: 0;
}

```

Теперь при изменении условия `@if` элемент будет плавно появляться и исчезать в течение 300 мс, вместо мгновенного добавления/удаления.

### Связывание с сигналами и выражениями

Атрибуты `animate.enter` и `animate.leave` поддерживают стандартный синтаксис привязки свойств `[animate.enter]`:

```html
@if (display()) {
  <div data-testid="with-binding" [animate.enter]="enterClasses()">
    Контент
  </div>
}

```

### Использование JavaScript-библиотек (GSAP и др.)

Если вы предпочитаете программные анимации через JavaScript-библиотеки (например, GSAP), можно использовать синтаксис привязки событий `(animate.enter)` и `(animate.leave)`:

**example.html**

```html
@if (display()) {
  <div data-testid="with-function" (animate.leave)="rotate($event)">
    Контент
  </div>
}

```

В обработчик передается объект типа `AnimationCallbackEvent`. Он содержит целевой элемент (`event.target`) и метод `event.animationComplete()`, который необходимо вызвать вручную после завершения анимации, чтобы Angular окончательно удалил элемент из DOM:

**example.ts**

```typescript
protected rotate(event: AnimationCallbackEvent) {
  gsap.to(event.target, {
    rotation: 360,
    duration: 0.3,
    onComplete() {
      // Сообщаем Angular, что анимация завершена и элемент можно удалять из DOM
      event.animationComplete();
    }
  });
}

```

## 31.3. Тестирование анимаций

По умолчанию в окружении `TestBed` анимации отключены, чтобы тесты выполнялись быстро и предсказуемо.

Если вам необходимо протестировать поведение элементов с учетом анимаций (например, проверить, что элемент удаляется из DOM только после завершения перехода), включите их в конфигурации тестового модуля с помощью параметра `animationsEnabled`:

```typescript
TestBed.configureTestingModule({
  animationsEnabled: true
});

```

С включенным флагом `animationsEnabled: true` элементы будут оставаться в DOM до тех пор, пока не отработают все связанные с ними переходы и анимации.

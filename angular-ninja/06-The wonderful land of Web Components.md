Смело пропускайте этот раздел, если эта тема вам неинтересна; тем не менее, я верю, что вы узнаете кое-что полезное для дальнейшего пути.

### 6.1. Прекрасный новый мир

Компоненты — старая мечта разработчиков. Что-то, что можно просто взять «с полки» и вставить в своё приложение — то, что заработает сразу и принесёт нужный функционал пользователям.

Друзья мои, это время пришло. Ну, почти. По крайней мере, появилось начало чего-то стоящего.

В этом нет ничего абсолютно нового. У нас уже довольно давно были компоненты в веб-разработке, но обычно они требовали наличия каких-то зависимостей: jQuery, Dojo, Prototype, AngularJS и т.д. Далеко не всегда это были те библиотеки, которые вы действительно хотели тянуть в свой проект.

Веб-компоненты пытаются решить эту проблему: давайте сделаем компоненты инкапсулированными и повторно используемыми из коробки.

Они опираются на набор формирующихся стандартов, которые браузеры пока поддерживают не идеально. Но всё же это интересная тема, даже если нам придется подождать несколько лет, чтобы использовать их в полной мере, или даже если эта концепция так и не «взлетит».

Этот стандарт определяется тремя спецификациями:

* **Custom elements** (Пользовательские элементы)
* **Shadow DOM** (Теневой DOM)
* **Template** (Шаблоны)

*Обратите внимание: приведенные ниже примеры, скорее всего, будут корректно работать в свежих версиях Chrome или Firefox.*

---

### 6.2. Custom elements (Пользовательские элементы)

Custom elements — это новый стандарт, позволяющий разработчикам создавать свои собственные DOM-элементы, делая конструкции вроде `<ns-pony></ns-pony>` абсолютно валидными HTML-тегами.

Спецификация определяет, как объявлять такие элементы, как расширять ими существующие теги, как задавать их API и т.д.

Объявление пользовательского элемента выполняется с помощью метода `customElements.define`:

```javascript
class Pony extends HTMLElement {
  constructor() {
    super();
    console.log("I'm a pony!");
  }
}

customElements.define('ns-pony', Pony);

```

И затем вы можете использовать его в разметке:

```html
<ns-pony></ns-pony>

```

Обратите внимание: имя элемента **обязано содержать дефис**, чтобы браузер понимал, что это именно пользовательский элемент.

Разумеется, ваш элемент может иметь свойства и методы, а также хуки жизненного цикла (*lifecycle callbacks*), позволяющие выполнять код при вставке или удалении компонента, а также при изменении одного из его атрибутов.

Он также может иметь собственный шаблон. Возможно, `<ns-pony>` отображает изображение пони или просто его имя:

```javascript
class Pony extends HTMLElement {
  constructor() {
    super();
    console.log("I'm a pony!");
  }

  /**
   * Вызывается, когда компонент вставляется в DOM
   */
  connectedCallback() {
    this.innerHTML = '<h1>General Soda</h1>';
  }
}

```

Если вы попытаетесь посмотреть на DOM-дерево, вы увидите `<ns-pony><h1>General Soda</h1></ns-pony>`.

Но это означает, что CSS-стили и JavaScript-логика всего вашего приложения могут оказывать нежелательное влияние на компонент. Поэтому обычно шаблон прячут и инкапсулируют внутри так называемого **Shadow DOM** (Теневого DOM), и при инспекции разметки вы увидите просто `<ns-pony></ns-pony>`, несмотря на то, что браузер отобразит имя пони на экране.

### 6.3. Shadow DOM (Теневой DOM)

От названия с таким загадочным оттенком ждёшь больших возможностей. И это действительно так!

Shadow DOM — это способ инкапсулировать внутренний DOM нашего компонента. Эта инкапсуляция означает, что стили и логика приложения не будут случайно применять свои правила к компоненту и ломать его. Это идеальный инструмент, чтобы скрыть внутреннее устройство компонента и гарантировать, что ничто не "протечёт" из компонента в приложение или наоборот.

Возвращаясь к нашему предыдущему примеру:

```javascript
class Pony extends HTMLElement {
  constructor() {
    super();
    const shadow = this.attachShadow({ mode: 'open' });
    const title = document.createElement('h1');
    title.textContent = 'General Soda';
    shadow.appendChild(title);
  }
}

```

Если вы попробуете проинспектировать этот элемент в браузере сейчас, вы увидите:

```html
<ns-pony>
  #shadow-root (open)
    <h1>General Soda</h1>
</ns-pony>

```

Теперь, даже если вы попытаетесь задать стили для глобальных элементов `h1` в вашем приложении, внешний вид компонента никак не изменится: Shadow DOM работает как защитный барьер.

До сих пор мы использовали просто обычные строки в качестве шаблона нашего веб-компонента. Но на практике делают иначе. Наилучший подход — использование элемента `<template>`.

### 6.4. Template (Шаблоны)

Шаблон, объявленный внутри элемента `<template>`, не отображается браузером сам по себе. Его главная цель — быть клонированным в какой-то элемент в нужный момент.

Всё, что вы объявляете внутри `<template>`, инертно: скрипты не исполняются, изображения не загружаются и т.д. Его содержимое нельзя найти с помощью обычных методов вроде `getElementById()`, и его можно безопасно разместить в любом месте вашей страницы.

Чтобы использовать шаблон, его нужно клонировать:

```html
<template id="pony-template">
  <style>
    h1 {
      color: orange;
    }
  </style>
  <h1>General Soda</h1>
</template>

```

```javascript
class Pony extends HTMLElement {
  constructor() {
    super();
    const template = document.querySelector('#pony-template');
    const clonedTemplate = document.importNode(template.content, true);
    const shadow = this.attachShadow({ mode: 'open' });
    shadow.appendChild(clonedTemplate);
  }
}

```

### 6.5. Фреймворки поверх Веб-компонентов

Все эти стандарты, собранные вместе, и образуют Веб-компоненты (Web Components).

Я далеко не эксперт в этой теме, да и на этом пути хватает всяких хитроумных подводных камней. Поскольку веб-компоненты поддерживаются браузерами не на 100%, вы можете подключить специальный полифил `web-component.js` в свое приложение, чтобы всё гарантированно работало. Стоит отметить, что этот полифил — результат совместной работы Google, Mozilla, Microsoft и других гигантов.

Поверх этого полифила появилось несколько библиотек. Все они направлены на упрощение работы с веб-компонентами и часто поставляются с набором готовых элементов.

Среди наиболее заметных инициатив:

* **Polymer** — первая попытка от Google;
* **LitElement** — более современный проект от команды Polymer;
* **X-tag** — от Mozilla и Microsoft;
* **Stencil**.

Я не буду вдаваться в подробности, но вы можете легко использовать уже существующий компонент. Допустим, вам нужна интерактивная карта Google Map в приложении:

```html
<!-- Полифил для поддержки Web Components в старых браузерах -->
<script src="webcomponents.js"></script>

<!-- Импорт элемента -->
<script src="google-map.js"></script>

<!-- Использование элемента -->
<body>
  <google-map latitude="45.780" longitude="4.842"></google-map>
</body>

```

В интернете существует ОГРОМНОЕ количество готовых компонентов. Посмотреть на них вживую можно на сайте [https://www.webcomponents.org/](https://www.webcomponents.org/).

С помощью LitElement и аналогичных фреймворков вы можете делать кучу крутых вещей: двустороннее связывание данных (two-way data binding), значения по умолчанию для атрибутов, генерацию пользовательских событий, реакцию на изменения атрибутов, повторение элементов при передаче коллекции и многое другое.

Эта глава, конечно, слишком коротка, чтобы рассказать абсолютно всё о веб-компонентах, но вы увидите, как некоторые из этих концепций будут всплывать по ходу чтения книги.

И вы точно заметите, что команда Google спроектировала Angular так, чтобы нам было максимально легко использовать веб-компоненты внутри наших компонентов Angular. Более того, с помощью пакетa **Angular Elements** мы даже можем экспортировать наши собственные компоненты Angular как полноценные нативные Web Components!

### Реакция на изменения сигналов

Мы только что рассмотрели, как использовать `ngOnChanges` для реакции на изменение входных данных (`inputs`). Это полезно, но не всегда удобно, если нужно отслеживать лишь некоторые из них. К тому же этот подход ограничен исключительно входными параметрами.

Сигналы обладают «суперсилой»: благодаря им Angular точно знает, когда представление (*view*), читающее сигнал, должно быть обновлено. И мы можем использовать эту суперсилу в своих целях с помощью двух функций: `computed()` и `effect()`.

---

#### 12.1. Вычисляемые сигналы (Computed signals)

Работали ли вы когда-нибудь с формулами в электронных таблицах? Это невероятно удобно: вы можете просуммировать значения в колонке продаж и записать результат в итоговую ячейку, а затем с помощью другой формулы рассчитать НДС от этой суммы. Если вы измените сумму продажи, автоматически пересчитаются и итоговая сумма, и НДС.

**Вычисляемые сигналы (`computed`)** работают точно так же.

Допустим, наш компонент пони получает модель `PonyModel` в качестве `input`, содержащую имя и цвет. Мы хотим выводить эти данные в формате `ИМЯ (цвет)` (например, `"RAINBOW DASH (blue)"`).

Первая мысль — записать это прямо в шаблоне:

```html
<div>{{ ponyModel().name.toUpperCase() }} ({{ ponyModel().color }})</div>

```

Этот вариант рабочий, но если приложение использует «грубый» механизм отслеживания изменений (*brute-force change detection*), это преобразование будет выполняться повторно при каждом цикле проверки, даже если модель пони не менялась.

Можно вынести логику в метод компонента:

```html
<div>{{ identity(ponyModel()) }}</div>

```

Это убирает дублирование в шаблоне, но метод `identity()` всё равно вызывается лишнее количество раз.

Другой путь — пересчитывать значение внутри `ngOnChanges` и записывать его в отдельный сигнал:

```typescript
readonly ponyModel = input.required<PonyModel>();
protected readonly identity = signal<string>('');

ngOnChanges() {
  this.identity.set(`${this.ponyModel().name.toUpperCase()} (${this.ponyModel().color})`);
}

```

Это уже лучше, но при добавлении других входных параметров значение будет пересчитываться даже при изменении посторонних данных (если только не усложнять метод `ngOnChanges`). Кроме того, нам приходится инициализировать сигнал `identity` фейковым значением.

Наиболее элегантное решение — использовать **вычисляемый сигнал (`computed`)**.

Вычисляемый сигнал — это сигнал **только для чтения** (*read-only*), значение которого выводится из одного или нескольких других сигналов:

```typescript
readonly ponyModel = input.required<PonyModel>();
protected readonly identity = computed(() => `${this.ponyModel().name.toUpperCase()} (${this.ponyModel().color})`);

```

Свойство `identity` теперь имеет тип `Signal<string>`. Angular автоматически отслеживает связь между `ponyModel` и `identity`: как только меняется `ponyModel`, меняется и `identity`.

##### Особенности `computed`:

* **Мемоизация и ленивость (Lazy):** значение вычисляется не в момент записи нового значения в исходный сигнал, а **только при первом прочтении** вычисляемого сигнала.
* Вычисления выполняются единожды и кэшируются до тех пор, пока исходные сигналы не изменятся снова.

Пример поведения:

```typescript
const count = signal(1);
const double = computed(() => {
  console.log(`computing double of ${count()}`);
  return count() * 2;
});

console.log(double());
count.set(2);
count.set(3);
count.set(4);
console.log(double());
console.log(double());
console.log(double());

```

Вывод в консоли:

```text
'computing double of 1'
2
'computing double of 4'
8
8
8

```

`computed` идеально подходит для создания производных состояний, зависящих сразу от нескольких сигналов (например, расчет цены с учетом количества, скидки и НДС):

```typescript
const total = computed(() => price() * quantity());
const totalAfterDiscount = computed(() => total() * (1 - discountRate()));
const vatIncludedTotalAfterDiscount = computed(() => totalAfterDiscount() * vatRate());

```

#### 12.2. Эффекты (Effects)

**Эффекты (`effect`)** — это еще один способ реагировать на изменения сигналов. В отличие от `computed`, они предназначены не для получения производных значений, а для **выполнения побочных эффектов** (*side effects*).

Примеры побочных эффектов:

* Сохранение значения сигнала в `localStorage` при его изменении.
* Ручное взаимодействие с DOM или вызов внешних API.

> **Важно:** Использовать `effect` для обновления других сигналов не рекомендуется — это может привести к бесконечным циклам. Для расчетов всегда выбирайте `computed`.

Пример использования эффекта для логирования:

```typescript
readonly ponyModel = input.required<PonyModel>();

constructor() {
  effect(() => console.log(`${this.ponyModel().name} - ${this.ponyModel().color}`));
}

```

##### Ключевые особенности `effect`:

1. **Привязка к контексту внедрения:** Эффект должен создаваться во время конструирования компонента (в `constructor` или при объявлении свойства), чтобы Angular мог автоматически уничтожить его вместе с компонентом.
2. **Первоначальный запуск:** Эффект **всегда выполняется один раз при инициализации**, чтобы Angular понял, от каких сигналов зависит функция.
3. **Асинхронность:** Эффекты выполняются асинхронно перед циклом проверки изменений. Промежуточные значения сигналов игнорируются — эффект получит только итоговое значение.

Пример асинхронного поведения:

```typescript
protected readonly score = signal(0);

constructor() {
  effect(() => console.log(`The score is now ${this.score()}`));
}

protected plusOne() {
  this.score.update(s => s + 1);
}

protected plusTwo() {
  this.plusOne();
  this.plusOne();
}

```

При создании компонента в консоли отобразится:

`"The score is now 0"` *(первоначальный запуск)*.

При вызове метода `plusTwo()` значение сигнала последовательно изменяется с `0` на `1`, а затем на `2`. Однако эффект сработает только после завершения обработки события и выведет:

`"The score is now 2"`.

---

#### 12.3. Итоги

Сигналы, `computed` и `effect` предоставляют понятный, выразительный и производительный инструмент для управления состоянием компонентов Angular.

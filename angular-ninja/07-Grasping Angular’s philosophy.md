### Понимание философии Angular

Чтобы писать приложения на Angular, необходимо усвоить несколько ключевых идей, лежащих в основе философии фреймворка.

Прежде всего, **Angular компоненто-ориентирован**. Вы будете писать небольшие компоненты, которые вместе образуют цельное приложение.

Компонент — это группа HTML-элементов внутри шаблона, предназначенная для решения конкретной задачи. Для этого обычно требуется логика, связанная с шаблоном — например, для наполнения данными или реакции на события.

Компонентный подход сейчас широко распространён среди фронтенд-фреймворков:

* **React** от Facebook делает так с самого начала;
* **Ember** использует собственный аналогичный подход;
* **Svelte** и **Vue.js** также делают ставку на построение небольших компонентов.

Angular не единственная в этом направлении, но она одной из первых (а может, и вовсе первой?) всерьёз позаботилась об интеграции с нативными Веб-компонентами (Web Components). Но пока отложим эту тему, так как она относится к более продвинутым.

Ваши компоненты будут выстроены в иерархическую структуру, аналогично DOM-дереву. Корневой компонент содержит дочерние компоненты, каждый из которых тоже может иметь собственных детей и так далее.

Если вы захотите отобразить гонки пони (а кто бы не захотел?), структура будет выглядеть примерно так:

* Главное приложение (`Ponyracer`);
* Меню (`Menu`) с вошедшим пользователем (`User`);
* Дочернее представление (`Race`), отображающее пони (`Pony`) на скачках.



Написание компонентов станет вашей ежедневной работой, поэтому давайте посмотрим, как они выглядят.

Команда Angular хотела задействовать ещё одно преимущество современной веб-разработки — **ES2015+**. Вы можете писать компоненты на ES5 (но это не очень круто) или на ES2015+ (гораздо круче!).

Но им этого показалось мало: они захотели использовать фичу, которая на тот момент ещё не являлась стандартом — **декораторы**. Поэтому разработчики Angular тесно сотрудничали с командами транспайлеров (Traceur и Babel), а также с командой TypeScript в Microsoft, чтобы мы могли использовать декораторы в приложениях Angular. Нам доступно несколько декораторов, позволяющих, например, легко объявлять компоненты. Надеюсь, вы всё это уже знаете, ведь я только что посвятил этим темам две главы!

Если упростить, компонент `Race` может выглядеть следующим образом:

```typescript
import { Component, inject, Signal, signal } from '@angular/core';
import { RaceModel, RaceService } from './services';
import { Pony } from './components';

@Component({
  selector: 'ns-race',
  templateUrl: './race.html',
  imports: [Pony]
})
export class Race {
  private readonly raceService = inject(RaceService);
  protected readonly race = signal(this.raceService.get());
}

```

А его шаблон выглядит так:

```html
<div>
  <h2>{{ race().name }}</h2>
  <div>{{ race().status }}</div>
  @for (pony of race().ponies; track pony.id) {
    <div>
      <ns-pony [ponyModel]="pony" />
    </div>
  }
</div>

```

Шаблон не должен вызывать сложностей для понимания. Это обычный HTML с выражениями в фигурных скобках `{{ }}`, которые вычисляются и заменяются соответствующим значением. Я не хочу сейчас погружаться слишком глубоко, моя цель — просто дать вам почувствовать, как выглядит код.

Компонент — это очень изолированный фрагмент вашего приложения. Само ваше приложение — такой же компонент, как и остальные.

Вы можете объединять компоненты в одну или несколько логических сущностей — **модулей** (модулей Angular, а не модулей ES2015), либо научиться обходиться без них, делая компоненты автономными (*standalone*). Вы также можете брать готовые библиотеки компонентов от сообщества и использовать их в своем проекте. Такие библиотеки могут предоставлять UI-компоненты, функциональность drag-and-drop, валидацию форм или всё то, что вы только можете вообразить.

В следующих главах мы изучим, с чего начать, как создать небольшой компонент, ваше первое приложение и синтаксис шаблонов.

Ещё одна концепция, лежащая в основе Angular — **внедрение зависимостей** (*Dependency Injection*, или сокращенно **DI**). Это очень мощный паттерн, и вы быстро привыкните к нему после прочтения соответствующей главы. Он особенно полезен для тестирования приложений, а я обожаю писать тесты и смотреть, как полоса прогресса в IDE становится зеленой. Это дает мне чувство отлично сделанной работы! Поэтому тестированию всего — ваших компонентов, сервисов и UI — будет посвящена отдельная глава.

В Angular всё ещё сохраняется то чувство магии, которое было в первой версии (v1), когда изменения автоматически отслеживались фреймворком и применялись к модели и представлениям. Однако сейчас это работает совершенно иначе: механизм отслеживания изменений использует концепцию **зон** (*zones*). Мы, разумеется, разберем и её.

Angular — это комплексный фреймворк, который предоставляет огромную помощь в решении повседневных задач веб-разработки. Работа с формами, HTTP-запросы к бэкенду, маршрутизация (routing), взаимодействие со сторонними библиотеками, анимации — всё, что угодно, уже предусмотрено.

Что ж, предстоит изучить немало вещей! Давайте начнем с самого начала: инициализируем приложение и напишем наш первый компонент.
